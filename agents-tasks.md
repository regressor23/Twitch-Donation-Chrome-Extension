# TipVault — розбивка на 4 агенти Claude Code

Старт робіт: 18.09.2026. Сабміт: 12.10.2026. Кожен агент — окрема гілка, окрема директорія, спільні контракти з `CLAUDE.md §4`.

**Порядок запуску:** спершу Агент A закриває `packages/shared` (memo-кодек + типи) — це блокер для всіх. Далі три агенти йдуть паралельно.

---

## Агент A — `program/` + `packages/shared`
**Роль:** Solana-інженер. Володіє контрактами й спільними типами.

### Спринт 1 (18–20.09) — розблокувати всіх
- `packages/shared`: `memo.ts` (encode/decode + фазз-тести), `types.ts` (Tip, Channel, ResolveResponse, AlertEvent), `networks.ts` (мінти, RPC, мінімальні суми, пресети $2/$5/$20).
- Скелет Anchor-програми, `anchor build` проходить.
- **DoD:** інші три агенти можуть імпортувати `@tipvault/shared` і писати код проти реальних типів.

### Спринт 2 (21–26.09)
- `tip_direct`, `tip_escrow`, `claim`, `refund_expired` + помилки з `CLAUDE.md §4.2`.
- Тести на localnet: happy path, подвійний клейм, клейм із чужою attestation, рефанд до/після `expires_at`, тіп менший за мінімум.
- Сервіс attestation: серверна функція підпису `AUTHORITY_SECRET` + верифікація в програмі (ed25519 instruction).
- **DoD:** `anchor test` зелений, деплой на devnet, program id зафіксований у `shared`.

### Спринт 3 (27.09–03.10)
- Деплой на mainnet, `upgrade authority` на мультисіг або спалена — рішення задокументувати в `/docs/security.md`.
- Скрипт-хелпер `buildTipTx()` у `shared`, яким користуються і web, і ext, і mobile (щоб три різні реалізації транзакції не розʼїхались).
- Оцінка compute units, priority fee-політика (окрема функція, бо на mainnet без неї транзакції зависатимуть у пікові моменти).
- **DoD:** одна функція будує транзакцію для всіх трьох клієнтів; mainnet-транзакція проходить за ≤ 3 с.

### Спринт 4 (04–11.10)
- Аудит власними силами за чеклістом: перевірка owner акаунтів, арифметика без переповнень, PDA-колізії, front-run клейму.
- `/docs/security.md` — модель загроз, що ми свідомо не робимо.

## Агент B — `web/`
**Роль:** фулстек. Найбільший обсяг, найраніший критичний шлях (оверлей).

### Спринт 1 (18–22.09)
- Next.js каркас, Supabase-схема з `CLAUDE.md §4.4`, міграції.
- `POST /api/webhooks/helius`: перевірка підпису, ідемпотентність по `signature`, парсинг memo, запис у `tips`.
- `GET /api/overlay/[token]/stream` (SSE) + сторінка `/overlay/[token]`: одна дефолтна анімація, звук, TTS-заглушка.
- Фолбек-полінг `getSignaturesForAddress` для активних каналів.
- **DoD:** devnet-транзакція → алерт на екрані ≤ 6 с. Це головна віха всього проєкту, вона має бути готова до 22.09.

### Спринт 2 (23–27.09)
- Twitch OAuth, дашборд стримера: підключити гаманець, отримати URL оверлея, ротація токена, історія тіпів.
- `GET /api/channel/[login]/resolve` — контракт для розширення й мобілки.
- Blinks: `GET/POST /api/actions/tip/[login]`, `actions.json`, реєстрація в Dialect Actions Registry (подавати одразу — верифікація займає час).
- Чат-бот: підтвердження тіпа в чат + повідомлення про unclaimed.
- **DoD:** blink анфьорлиться в X через Phantom; бот пише в чат тестового каналу.

### Спринт 3 (28.09–04.10)
- Клейм-флоу: `POST /api/claim` → attestation → транзакція з дашборда.
- Сторінка збору (charity mode): on-chain прогрес-бар, публічна сторінка звіту, віджет-версія для OBS.
- Алерт-паки: 5 готових наборів у `/public/packs`, вибір у дашборді, TTS через cabina.ai MCP з фолбеком на браузерний SpeechSynthesis.
- Лендинг (uk/en) + сторінка «SEPay вимикають — куди переїхати» під органіку.
- **DoD:** новий стример проходить шлях «зайшов → підключив гаманець → вставив browser source → отримав тестовий алерт» за ≤ 3 хвилини без допомоги.

### Спринт 4 (05–11.10)
- Mercuryo on-ramp у попапі й на сторінці тіпа.
- `GET /api/stats/[channelId]` + внутрішня панель метрик пілоту (кількість алертів/день — головне число).
- Навантажувальний тест SSE: 50 одночасних оверлеїв, 10 алертів/с.

## Агент C — `ext/` (Chrome MV3)
**Роль:** фронтенд-інженер із досвідом браузерних розширень. Найбільший ризик — ревʼю стору, тому подача 03.10, не пізніше.

### Спринт 1 (22–26.09)
- Vite + TS + React, MV3-маніфест із мінімальними permissions (`storage`, `https://*.twitch.tv/*`, власний API).
- Content script: визначення каналу з URL і DOM, вставка кнопки Tip під плеєром і в чат. Стійкість до зміни розмітки Twitch: три селектори-кандидати + MutationObserver, при невдачі — фолбек на плаваючу кнопку, а не поламаний UI.
- **DoD:** кнопка живе після ресайзу, переходу між каналами, theatre mode і повного перезавантаження SPA.

### Спринт 2 (27.09–02.10)
- Попап: пресети, поле повідомлення з лічильником символів під ліміт memo, виклик `resolve`, побудова транзакції через `buildTipTx()`.
- Підпис: deep-link у Phantom (desktop extension provider), фолбек — Solana Pay QR для телефону.
- Стан «канал ще не зареєстрований» → escrow-режим із чесним поясненням «стример забере після підтвердження, інакше поверне тобі через 30 днів».
- **DoD:** повний шлях тіпа з реального twitch.tv на mainnet.

### Спринт 3 (03.10) — подача в Chrome Web Store
- Privacy policy, обґрунтування permissions, скріншоти, промо-відео 30 с, опис uk/en.
- **DoD:** статус «in review» зі скріншотом (іде в сабміт як доказ, навіть якщо публікація не встигне).

### Спринт 4 (04–10.10)
- On-ramp-кнопка, історія власних тіпів, бейдж «ти в топ-3 сапортерів каналу».
- Firefox-збірка — тільки якщо лишається час. Не блокер.

## Агент D — `mobile/` (Expo, Solana Seeker)
**Роль:** мобільний інженер. Працює автономно, його реліз — диференціатор сабміту.

### Спринт 1 (24–29.09)
- Expo-каркас, Mobile Wallet Adapter, підпис через Seed Vault на Seeker.
- Viewer-режим: скан QR з екрана стрімера → сума → підпис → готово. Ціль — 3 секунди від скану до підпису.
- **DoD:** тіп із фізичного Seeker проходить на devnet.

### Спринт 2 (30.09–05.10)
- Creator-режим: баланс, історія, пуші «прийшов тіп», клейм ескроу з телефона.
- Deep-links `tipvault://tip/<login>` + universal links із лендингу.

### Спринт 3 (06–09.10) — публікація
- `dapp-store` CLI: NFT-паблішинг, асети, опис, вікові рейтинги, збірка релізного APK.
- **DoD:** заявка в Solana dApp Store подана, скріншот у сабміт.

### Спринт 4 (10–11.10)
- Запис мобільного фрагмента демо-відео: Seeker у руці, QR з екрана, алерт спрацьовує на стрімі. Це найсильніші 20 секунд усього ролика.
